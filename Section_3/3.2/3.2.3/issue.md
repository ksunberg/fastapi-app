# Задача 3.2.3 — Сессии с автопродлением

## Описание
Доработать cookie-аутентификацию: реализовать сессии с динамическим сроком жизни и защитой от подделки.

## Формат cookie
```
<user_id>.<timestamp>.<signature>
```

- `user_id` — уникальный идентификатор (UUID);
- `timestamp` — время последней активности (UNIX timestamp);
- `signature` — криптографическая подпись обоих значений.

## Правила продления сессии
- Сессия действует **5 минут** после последней активности.
- Запрос, поступивший спустя **3–5 минут** с последней активности → сессия продлевается ещё на 5 минут.
- Запрос спустя **менее 3 минут** → кука не обновляется.
- Запрос спустя **более 5 минут** → доступ запрещён (401).

Пример: логин в 10:00 (действует до 10:05) → запрос в 10:02 не продлевает, в 10:03 продлевает до 10:08, в 10:07 продлевает до 10:12, в 10:16 — отказ.

## Задачи
1. **`POST /login`** — устанавливает куку `session_token` с текущим временем активности. Параметры: `httponly=True`, `secure=False`, `max_age=300`.
2. **Защищённый маршрут** (например, `GET /profile`):
   - проверяет целостность данных (подпись) и актуальность сессии;
   - при успехе возвращает профиль и при необходимости обновляет куку.
3. **Обработка ошибок:**
   - недействительная/просроченная сессия → 401 `{"message": "Session expired"}`;
   - поддельные данные → 401 `{"message": "Invalid session"}`.

## Критерии успешности
- Сессия не продлевается, если прошло более 5 минут.
- Время в куке синхронизировано с серверным временем.
- Любое изменение данных в куке → немедленный запрет доступа.

## Тестирование
- Postman с задержкой между запросами (например, 2 минуты).
- Ручное изменение `session_token` в браузере для проверки реакции сервера.
- Сценарии: запрос через 2 мин → без обновления; через 4 мин → обновление; через 6 мин → 401; изменённый идентификатор → 401.

> Чтобы изменить статус-код ответа, используйте объект `Response` из FastAPI (`response.status_code = 401`).
