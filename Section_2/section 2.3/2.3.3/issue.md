# Задача 2.3.3 — Многоуровневая валидация отзывов

## Описание
Усовершенствовать систему отзывов: вложенные модели, расширенная валидация и поддержка параметров запроса.

## Требования к моделям
- Вложенная модель `Contact`:
  - `email` — обязательное поле с валидацией формата;
  - `phone` — опциональное поле (только цифры, 7–15 символов).
- Основная модель `Feedback`:
  - `name` — строка 2–50 символов;
  - `message` — строка 10–500 символов.

## Бизнес-логика
1. Автоматически проверять `message` на запрещённые слова («редиска», «бяка», «козявка» в любых формах).
2. Реализовать параметр запроса `is_premium`:
   - при `true` добавлять фразу **«Ваш отзыв будет рассмотрен в приоритетном порядке»** к ответу.

## Примеры
**Стандартная обработка** — `POST /feedback`:
```json
{
    "name": "Артём",
    "message": "Понравилась структура курса: теория сразу закрепляется практикой",
    "contact": {"email": "artem@study.ru"}
}
```

**Ответ:**
```json
{
    "message": "Спасибо, Артём! Ваш отзыв сохранён."
}
```

**Приоритетная обработка** — `POST /feedback?is_premium=true`:
```json
{
    "name": "Виктория",
    "message": "Подробные примеры из реальных проектов помогают понять нюансы разработки",
    "contact": {"email": "vika@protonmail.com", "phone": "79051234567"}
}
```

**Ответ:**
```json
{
    "message": "Спасибо, Виктория! Ваш отзыв сохранён. Ваш отзыв будет рассмотрен в приоритетном порядке."
}
```

## Критические точки валидации
- Сообщение ровно в 500 символов должно проходить проверку.
- Телефон `"7905123"` (7 цифр) — допустим; `"7905123a"` — ошибка.
- Сообщение со словом «козявка» должно блокироваться.
