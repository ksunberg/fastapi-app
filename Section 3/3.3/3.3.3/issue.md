# Задача 3.3.3 — Проверка версии приложения

## Описание
Добавить в модель заголовков проверку версии фронтенда (заголовок `X-Current-Version`) и блокировать устаревшие версии.

## Задачи
1. **Модификация модели `CommonHeaders`:**
   - добавить обязательное поле `X-Current-Version` с форматом трёх целых чисел, разделённых точкой;
   - указать ожидаемый формат в OpenAPI-документации (`pattern`);
   - добавить кастомный валидатор: если версия ниже базовой `MINIMUM_APP_VERSION = "0.0.2"`, выбрасывать `ValueError("Требуется обновить приложение")` → HTTP 422.

2. **Интеграция в маршруты:**
   - `GET /headers` — возвращает `User-Agent` и `Accept-Language`; при устаревшей версии — 422;
   - `GET /info` — возвращает приветствие, заголовки и `X-Server-Time`; при устаревшей версии — 422.

## Сценарии проверки
| `X-Current-Version` | Ожидаемый ответ |
|---|---|
| `0.0.1` | 422 — требуется обновление |
| `0.0.2` | 200 OK |
| `1.0.0` | 200 OK |
| `a.b.c` | 422 — ошибка формата |

## Правила сравнения версий
- `0.0.1 < 0.0.2` → устаревшая (422);
- `0.1.0 > 0.0.11` → допустимая;
- `2.0.0 > 1.100.500` → допустимая.

> Цель — симулировать на бэкенде проверку версии мобильного приложения и ограничивать доступ устаревших клиентов.
