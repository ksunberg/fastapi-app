# Задача 7.2.2 — Мокирование HTTP-запросов (respx)

## Описание
Научиться мокать исходящие HTTP-запросы в тестах FastAPI с помощью `respx`, не выполняя реальных сетевых вызовов, и проверять взаимодействия.

## Задачи

### 1. Мини-сервис (1 эндпоинт)
`GET /weather?city=...` — через `httpx.AsyncClient` обращается к внешнему API (`https://api.example.com/weather`) и возвращает нормализованный ответ:
```json
{"city": "<имя>", "temp_c": <число>}
```
Ошибки внешнего сервиса преобразовывать в HTTP-ответы: 5xx → 502, таймаут → 504.

### 2. Структура кода
Логику HTTP-клиента вынести в отдельный модуль/функцию (например, `clients/weather.py: get_weather(city)`). Эндпоинт только вызывает её и преобразует результат.

### 3. Тесты на pytest с respx
Использовать фикстуру `respx_mock` или `respx.mock`; настроить `base_url` и проверки роутера (`assert_all_mocked`, `assert_all_called`).

**Обязательные сценарии:**
| Сценарий | Действие | Ожидаемый ответ |
|---|---|---|
| Счастливый путь | внешнее API → 200 + валидный JSON | 200 и правильное тело |
| Ошибка 5xx | внешнее API → 500 | 502 с понятным описанием |
| Таймаут | `httpx.ReadTimeout` через `side_effect` | 504 |
| Неожиданный ответ | 200, но нет поля `temp_c` | 502 или 422 |

### 4. Проверки взаимодействий
- Маршрут вызван ровно 1 раз (`route.called`, `route.call_count`, `respx.calls.assert_called_once()`).
- Проверить метод, путь и параметры запроса (`params={"city": ...}`), при необходимости — заголовки.
- Отсутствие немокированных обращений (`assert_all_mocked=True`).

## Ограничения
- Без реальных внешних API — только respx.
- Тесты асинхронные: `pytest-asyncio` + `httpx.AsyncClient`.
- Отделять подготовку моков от проверок для читаемости.

## Критерии приёма
- Все четыре сценария покрыты тестами и проходят.
- Нет реальных сетевых вызовов.
- Проверены вызовы (количество/аргументы), статусы и тело ответа.
- Код разделён: эндпоинт ↔ клиент внешнего API.
