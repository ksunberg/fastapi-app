# Задача 4.3.1 — RBAC: управление доступом по ролям

## Описание
Реализовать контроль доступа на основе ролей (RBAC). Предполагается, что JWT-аутентификация уже реализована, а роли назначаются при регистрации.

## Задачи
1. Определить минимум три роли и их разрешения:
   - **admin** — полные права CRUD;
   - **user** — чтение и обновление ресурсов;
   - **guest** — только чтение.
2. Реализовать авторизацию по ролям через внедрение зависимостей или декораторы: проверять роль перед доступом к эндпоинтам.
3. Создать `GET /protected_resource`, требующий аутентификации; доступ только для ролей admin и user.
4. Для каждой роли создать отдельные эндпоинты, демонстрирующие её разрешения (например, admin создаёт ресурс, user читает/обновляет).
5. Протестировать RBAC, отправляя запросы с разными ролями и убеждаясь, что доступ корректно ограничивается.

> Для хранения ролей и разрешений можно использовать словари Python или in-memory хранилище. В реальном проекте RBAC интегрируется с БД.
